## Root cause: why the old pigmentation was weak

The existing atomic garment compositor correctly prevents the white intermediate shirt, but colors were generated by multiplying every original near-white source channel by 0.26 + 0.74 × pigmentChannel/255. Most opaque source-garment pixels have encoded-lightness medians 236–242/255. A zero-valued black pigment channel therefore still contributes roughly 26% of this source brightness; a color like the old black swatch (#292b2a) produced an output around [91,92,90] — visibly gray, not black. The red swatch (#bf3846) produced roughly [195,100,109], an unsaturated muted pink. Simply increasing opacity would cause shadows and highlights to flatten and might introduce darker unwanted fringe tones.

Measured 1536-width source WebP median luma:
- Regular Tee: 242/255
- Drop Shoulder: 237/255
- Full Sleeve: 236/255
- Hoodie: 238/255

The source neutral garment artwork is therefore a material-lightness / fold / seam map, not an RGB pigment reference.

## Color science and independent calibration

A new isolated source module, src/worktable-fabric-pigments.mjs, separates pigment calibration from the renderer and the original illustrated pot colors:

| Fabric | Calibrated base pigment | Treatment |
|---|---|---|
| Black | #222629 | Deep near-neutral black, CIE L* lightness-modulated highlight/shadow difference, capped floor |
| White | Original pixels | No recoloring, retains all white folds, seams, natural texture |
| Red | #DE1F30 | High-chroma red with bounded tone mapping |
| Yellow | #F3C916 | Rich golden yellow, controlled highlight ceiling |
| Blue | #145FCE | Saturated cool blue, preserved chroma in folds |
| Green | #087B47 | Strong saturated fabric green |

The illustrated **six paint-pot swatches remain exactly unchanged**, retaining their original #292b2a / #ffffff / #bf3846 / #e1bc33 / #2a6ea9 / #317452 color-control values. These are not silently substituted for the fabric calibration profiles.

The engine derives source encoded BT.709 neutral luma, maps that luma through the sRGB transfer function into CIE L* lightness, and uses each garment's measured neutral reference to calculate a **shared tonal scalar** for calibrated chromatic pigments (not an RGB-channel multiplication against white). Fold lightness changes pigment intensity while retaining the chosen hue. For black, a near-neutral additive lightness ramp gives plausible dark cotton with restrained reflected highlights. Both shadows and highlights are bounded to prevent clipping, gray wash or artificial black crush.

The nonlinear curve is precomputed into a 256-entry × 3-channel **768-byte lookup table** for each colorization call. Browser pixel loops use one neutral-luma lookup rather than per-pixel exponentials. White bypasses this path. The original RGBA alpha channel is never modified; no outside-silhouette pixels are painted. Original RGB neutral source and its unmodified white rendition remain available via the same optimized WebPs.

## Performance comparison and memory impact

Both the original and calibrated algorithm were measured in the **same headless browser processes**, with identical browser-side Canvas2D draw-to-putImageData instrumentation. 24 garment/color passes per comparison profile; measurements are single experimental runs, not a physical iPad guarantee.

| Browser / viewport | Before pigment median / p95 | Calibrated pigment median / p95 |
|---|---|---|
| WebKit tablet, 834px DPR2 | 30ms / 67ms | 23ms / 67ms |
| Chromium desktop, 1440px | 9.2ms / 12.2ms | 10.3ms / 15.5ms |
| Chromium mobile, 390px | 2.3ms / 3.8ms | 2.3ms / 2.5ms |

Retina WebKit worst observed complete pigment pass dropped 112ms → 82ms in the controlled paired run. The Chromium desktop median increased about 1.1ms, with no meaningful loss of interaction readiness.

Measured Chromium retained **JS heap change** after 24 combinations (GC before/after):
- Desktop: 175,036 B before vs 203,008 B calibrated; additional 27,972 B retained.
- Mobile: 193,812 B before vs 201,288 B calibrated; additional 7,476 B retained.

The new engine adds a 256-element lightness lookup (~1KB) and a 768-byte pigment LUT during each recolor, while retaining the existing garment canvas size and original number of responsive WebP sources. Full GPU/browser-process memory and physical-iPad memory are **not measured**. The recorded retained JS heap excludes GPU textures, canvas backing allocations and operating-system memory; it must not be presented as total RAM.

All **8/8 relative performance gates PASS**: first usable scene within the previous baseline +350ms, colorization p95 within baseline ×1.4 +5ms, and retained heap growth below an additional 256KiB on Chromium. The first frame still uses the identical optimized preassembled worktable WebP and no extra image asset is requested at load. [Raw paired performance metrics and gates](performance-evidence/fabric-pigmentation-20261108/render-performance.json).
